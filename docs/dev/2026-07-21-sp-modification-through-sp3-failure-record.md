# SP 改造から SP3 までの実験・失敗記録

作成: 2026-07-21

この文書は、`SPCalculator` の高速化から SPv2 / SP3 補助教師までの試行を、
同じ方向を再提案しないために残す失敗台帳である。現在の `main` は
`d41e671`（SP 高速化マージ前）を基点としており、以下の実験コードは含まない。
数値と判断だけを履歴として保存する。

## 結論

- SP 最大 EV ラベルを補助教師にしても、DQN の牌効率や対局性能へ転移しなかった。
- 手変わり（tegawari）を考慮すると教師の人間打牌一致は改善するが、計算コストと
  分離できない。キャッシュ不要な設定では、その品質差も消える。
- SPv2 は 162k step、再テストは 50k step で中止した。SP3 は学習へ進む前の
  速度・品質検証で中止した。
- SPv2 / SP3 は廃止する。再試行する場合は、下記の失敗要因を変える明確な機構と、
  低コストの事前反証を必須とする。

## 1. SPCalculator の高速化

- 実装: `b27aa5e`、統合: `cbf4e6c`
- 内容: シャンテン計算と SP の内部処理を改造し、CPU 時間を約 2.3 倍高速化。
- 出力は既存実装とビット同一であり、これは性能改善ではなく計算最適化だった。
- 後続の SP 実験を含む履歴を整理するため、`main` は統合直前の第1親
  `d41e671` へ戻した。したがって、この高速化自体も現在の `main` にはない。

## 2. SP 評価ラベルとフルラベル

旧評価用 SP は `calc_tegawari=false`、`calc_shanten_down=false` で、手変わりや
向聴戻しを評価できなかった。そこで両方を有効にしたフルラベルを並行実装し、
64ファイル・12,467決定点で既存 checkpoint を再採点した。

主な結果:

- 手変わり・向聴戻しを考慮すると、SP 最適打牌の 34.0% が変化した。
- 無スレット局面では、旧 SP が表外としていたモデル打牌の約 59% が、
  フルラベルでは最適打だった。旧 SP 指標には大きな計測アーティファクトがあった。
- 一方、オンライン劣化はフルラベルでも確認された。無スレットの EV 損失は
  22.9 → 26.6 → 32.2、一致率は 0.581 → 0.522 → 0.466 と単調に悪化した。
- 計算コストは2ファイルで、ラベルなし 0.66秒、旧 SP 1.20秒、フルラベル
  57.7秒。旧 SP の約48倍で、学習のホットパスには置けなかった。

この結果から、旧 SP は牌効率の絶対評価として不完全であり、フルラベルは診断には
有用だが、オンザフライ教師としては高コストすぎると判断した。

関連コミット: `fdb9705`, `11e7da3`, `0fa0a5d`, `8d34893`

## 3. SPv2 補助教師

SPv2 はフルラベルを事前計算し、共有表現へ softmax 教師として追加する方式だった。

- 0～2向聴: tegawari と向聴戻しを有効化
- 3向聴: tegawari のみ有効化
- 30,000ファイルの NPZ キャッシュを使用
- 脅威のない行だけに補助損失を適用
- SPv2 loss weight 0.1、既存の MC-Q + CQL は維持

結果:

- 新規オフライン run を約162k stepで中止した。
- held-out の `model_match_rate_no_threat` は 0.571 → 0.594 → 0.587 と微動し、
  牌効率指標や test_play への転移は確認できなかった。
- `min_q_weight=5` に戻した再テストでも、50k step 時点で対照との差はノイズ内だった。
- ラベル自体は学習しても、実際に使う DQN head へ有効な改善が移らなかった。
- 評価時にラベルを再計算すると、suite は約64秒から約1,050秒へ増加した。
  約16倍の遅延で、短い反復検証が不可能になった。
- 有効な教師行が約7%と薄く、30kファイルのキャッシュ上限、脅威行マスク、
  補助 head と DQN head の目的不一致が失敗要因候補として残った。

結論: 「SP ラベルを学習できる」ことと「DQN の方策が改善する」ことは別であり、
SPv2 の補助教師方式には転移がなかった。

関連コミット: `c6efe6f`, `adca746`

## 4. SP3

SP3 は、旧 `expected_value_calculator` ではなく、新しい mahjong-cpp の
`expected_score_calculator`（グラフ構築 + 後ろ向き帰納法）を Rust に移植した
SPv2 後継候補だった。

### 速度

8ファイル・1,550決定点の同条件ベンチ:

| エンジン | ラベル生成時間 |
|---|---:|
| SPv2 | 16.56秒 |
| SP3 | 35.09秒 |

SP3 は SPv2 より約2倍遅かった。riichi 状態次元の除去、裏ドラ DP の無効化、
シャンテン計算回数の半減を個別に試したが、速度比は約0.48のまま変わらなかった。
コストはグラフ全体の実体化、ハッシュ表、CSR構築、別パス DP に分散しており、
局所最適化では解消できなかった。

### 品質

48ファイル・3,043決定点で、最大 EV 打牌と強者ログ打牌の一致を比較した。

| 向聴帯 | SPv2 | SP3 |
|---|---:|---:|
| 全体 | 0.554 | 0.636 |
| 0向聴 | 0.785 | 0.896 |
| 1向聴 | 0.624 | 0.719 |
| 2向聴 | 0.541 | 0.630 |
| 3向聴 | 0.503 | 0.570 |

SP3 は全体で +8.2ポイント（約6 SE）改善し、教師品質は明確に高かった。

### 品質とコストの分離不能

| SP3設定 | 人間打牌一致 | 速度・運用 |
|---|---:|---|
| tegawari 無効 | 0.546 | 約20倍高速、キャッシュ不要 |
| tegawari ≤1向聴 | 0.612 | SPv2並み、キャッシュ必要 |
| tegawari ≤3向聴 | 0.636 | SPv2の約2倍遅い、キャッシュ必要 |

tegawari を無効にすると、新エンジン単体の品質は元の SP とほぼ同等になった。
品質向上は新エンジンへの置換そのものではなく、計算量の大きい tegawari 探索に
由来していた。したがって「品質を保ったままキャッシュ不要にする」経路はない。

結論: SP3 は SPv2 より良質だが遅く、品質を出す設定では SPv2 と同じキャッシュ・
反復速度問題を継承する。さらに SPv2 で補助教師から DQN への転移がなかったため、
高コストな学習パイロットには進まなかった。

関連コミット: `fe7f11f`, `846bebd`, `c9a6d75`, `69eec4c`

## 今後この方向を再検討する条件

単なる SP ラベル、温度、loss weight、キャッシュ量の変更では再試行しない。
少なくとも次のいずれかが必要:

1. 補助 head ではなく、探索で得た改善行動分布を実際の方策へ直接蒸留する。
2. tegawari 相当の品質を、反復可能な別アルゴリズムで得る。
3. 低い教師カバレッジと脅威局面マスクを解消しつつ、守備を壊さない目的関数を示す。
4. 20k step 以下の安価な事前ゲートで、held-out 牌効率と対局性能への転移を確認する。

上記の機構差がない限り、SPv2 / SP3 補助教師路線は終了扱いとする。
