## 1. 現状認識（2026-07 時点）

- モデル: v4、192ch × 40blocks、MC-Q 回帰（オフライン CQL → オンライン自己対戦）
- **性能の現況**: オフライン（50万半荘・強者抽出）で和了率 22%、牌効率に残欠。オンライン継続で和了率 20% に低下し、**引き気味の守備的均衡に収束**する。「サンプル量で打開」路線は頭打ちを確認済み
- 問題の構造（notes セクション4）: 人間データの BC 錨 × MC リターンの高分散 × 2フェーズの分布シフト × 順位という遅い評価が絡む非線形システム。**理論の正しさでは勝てない**。最適戦略はフィードバックループを短くし、失敗を安く可視化し、壊れたら戻れるようにして1変数ずつ動かすこと
- 運の定量的正体（C-1 実験で決着）: 局報酬分散の**約89%は決定時点の完全情報（山・全員の手）をもってしても説明不能**。ノイズ源は「現在の隠れ状態」ではなく「未来の乱数と4人の方策エントロピー」。→ 分散削減は条件付け（ベースライン）ではなく**ターゲット側の変更**（duplicate 平均、ブートストラップ）でしか到達できない
- **オンライン劣化の機構（Phase A ステップ3、2026-07-15 suite_batch で決着）**: DQN オンライン run 末期の top-k（1100k→1140k→1180k、8万 step、同一条件採点）で `sp/model_ev_loss` 24.3→26.5→30.2、`human_top1` 0.787→0.774→0.745、`q/top1_top2_margin` 1.19→0.95→0.66 と**全軸が単調劣化・減速なしのまま run 終了**。「守備的均衡への収束」ではなく**CQL 錨消失による進行性ドリフト**が実態。かつこれらは test_play ゲートを通過して top-k に残っていた = **test_play 単独では劣化を検出できない**（「遅い評価」の罠の実証）。オフライン群（2024 上流 best 含む4モデル）は全指標 ±0.005 に収束しており、オフライン学習の固定点は再現性が高い
- **regime 判別則（2026-07-16 確立）**: 成熟オフライン帯 = human_top1 0.830〜0.835 / ev_loss_no_threat 14.2〜15.6。`(ev_loss↑, human_top1↑)` で帯内 = 文脈学習（健全な成熟）、`(ev_loss↑, human_top1↓)` で帯を突破 = 錨なしドリフト（病理）。オンライン監視の主軸は `sp/model_ev_loss_no_threat`（単調・高速に動くため 4 万 step で検出可能）

### 失敗・没（理由つき）

| 施策 | 結果と理由 |
|---|---|
| **サンプル増のみでの打開** | 頭打ち。高速化・分散化で投入量を増やしても avg_rank 改善せず |
| **AWBC**（advantage = return − V の指数重み BC） | 効果なし。advantage 分散の9割が除去不能ノイズのため、exp(adv/β) は実質「運の指数重み付け」になる（C-1 実験で機構が確定）。実装は残置（デフォルト off） |
| **C-1 運補正ベースライン b(s, z)**（train_baseline.py） | 棚上げ。オラクル情報（山・全手牌）の R² 増分は +0.006 のみ（凍結トランク φ 単独 0.110 に対し）。2回の学習 + 閉形式 ridge プローブで決着。**副産物**: ①回帰ヘッドはこのパイプラインで丸暗記する（同一局ターゲットが近接バッチに反復）②凍結 φ は R²=0.11 の汎化信号を持つ ③ウォームスタート転移コード（第1conv ゼロ拡張、bit 一致検証済み）は補助タスクに再利用可 |
| **critic / V ベースライン追加**（複数回） | 全て「無意味」化して失敗。理由は上と同根: V で条件付けしても除去できる分散がほぼない |
| **オンラインでの CQL/BC 正則化** | 不採用（試行の結果） |
| **対戦相手プール**（opponent_pool） | 不採用（試行の結果）。機能自体は残置（`opponent_pool_dir/prob`）。再挑戦時は「押しの成功体験の供給」という目的を明確化し suite のスタイル指標で監視すること |
| **方策勾配版**（別リポジトリ `Mortal-P-Modtest`: offline AWR-BC → online PPO、critic なし） | オンラインで DQN 版より悪い。**敗因を suite_batch で定量化（2026-07-15）**: PPO 継続で `ev_loss_no_threat` 16.3→21.1（315k→765k）、向聴後退率 2 倍、advance_miss 0.041 — 牌効率の崩壊。なお policymodel（AWR-BC + ごく短い PPO）はオフライン同等のプロファイルを維持しており、既知の弱点（リーチ判断・七対子・トップ目進行）は現行 suite の死角（点数状況・手型スライス未実装）。系統識別: 20251007/20260205 online は policy ヘッドを checkpoint 検査で確認、315k/765k は時期・挙動から同系と推定 |
| **bf16 重み化**（`weights_dtype='bfloat16'`） | 不採用。checkpoint 依存で行動一致率 0.9639（基準 0.995 未達）、速度益も +5-10% のみ |

### 上流由来の未使用インフラ（検討済み・保留）

- **Oracle 蒸留**: `Brain(is_oracle=True)` と invisible_obs のインフラは存在、train.py 未使用。工事が大きい。C-1 の「隠れ情報の増分 R²=+0.006」という結果は**価値予測**への増分であり、**方策蒸留**の価値を直接否定はしないが、期待値は下方修正して扱う
- **分位点ヘッド（QR-DQN 風）**: 多峰リターン対策の本命候補だが checkpoint 互換の工事が大きい。Huber で一部代替済み
- **TD(λ)/n-step + ターゲットネット**: 局内クレジット割り当て。C-1 の結論（ターゲット側変更が正道）とは整合するが、λ-return 系は過去に計画のみで未実施
- **model soup / EMA**（top-k candidates の重み平均）: ほぼ無料。未実施
- **GRP の自己対戦データ再学習**: 自己対戦が進むと報酬モデルが OOD になる問題。train_grp.py は既存

## 3. 基本戦略

1. **観測に投資する**: 個々の介入の多くは効かない前提で臨む。計画の価値は当たりの保証ではなく、**外れを数日と曲線1本で確定させ、当たりだけが積み上がる構造**にすること
2. **安い反証を先に**: 数週間の再学習の前に、線形プローブ（1時間）や suite の採点（数分）で見込みを判定する
3. **可逆性**: top-k candidates + gate_sigma でいつでも巻き戻せる状態を維持
4. **obs チャンネルは変えない**: 全 checkpoint・baseline・プールとの非互換（実質 version 5）になる。入力追加ではなく**後知恵ラベルの補助タスク**（obs 不変・opt-in）で同じ目的を達成する（notes セクション3 案C）

成功基準: checkpoint 間で suite 指標が単調・低ノイズに動くこと（test_play SE ±0.02 で見えない差が見えること）。

### Phase B: 線形プローブによる安い反証（補助タスク投入の前提ゲート）

C-1 で作った閉形式 ridge プローブ資産を再利用。凍結トランク φ に対して後知恵ラベルを線形回帰/分類:

- 牌種ごとの山の実残数（34次元 0–4、`invisible.rs` がパース済み）
- 各他家の聴牌有無・待ち牌

判定:
- **プローブ精度が既に高い** → 情報は φ にあり補助タスク不要 → 数週間の再学習を回避（この結果自体が成果）
- **低い** → Phase C の勝ち筋あり。プローブ精度は以後「場況読み獲得度」メトリクスとして常設

### Phase C: 後知恵ラベルの補助タスク（プローブが正当化した場合のみ）

notes セクション2–3 の案C。obs 不変・AuxNet 拡張・opt-in。

- ラベル候補（優先順): ①打牌後の受け入れ枚数回帰 / SP 最適打牌分類（序中盤の牌効率信号の薄さ対策）②山残数・他家聴牌/待ち（場況読み）
- 実装: 凍結トランクでヘッドをウォームスタート → 小さい重みで解凍（C-1 の転移コード再利用）
- **丸暗記対策必須**（C-1 副産物①): reserve_ratio > 0 / file_batch_size 増 / ファイル内サブサンプリング、held-out 検証を必ず付ける
- 干渉監視: `grad/aux_norm` / `grad/dqn_norm`、suite の全指標
- 中止基準の例: 20k ステップで suite/efficiency が改善せず、または held-out ラベル精度が train と乖離（丸暗記）したら revert

### Phase D: オンライン守備的均衡の打破

Phase A で機構を観測してから着手（対策の選択は観測結果に従う）。候補メカニズムと対応（notes セクション4-3）:

| 機構仮説 | 対策候補 | 備考 |
|---|---|---|
| (a) CQL が切れて錨がない | リプレイ混合（人間牌譜を1〜2割、dataloader のファイルリスト混合で実装可） | **実験中（2026-07-16〜、ブランチ `exp/online-replay-mix`、メイン PC）**。`[online] replay_mix_ratio`（デフォルト 0 = bit 同一）。Phase A の機構観測（§1）が根拠。**成功基準**: オンライン 80k step で `sp/model_ev_loss_no_threat` が開始値 +1 点以内かつ帯上限 15.6 以内、`human_top1_no_threat` 低下 1pt 以内、test_play 悪化 gate_sigma 以内。**中止基準**: 1100k→1180k 型の単調上昇が 3 境界連続で再現、または behavior/* が許容帯外 |
| (b) 強 baseline 3人相手で押しの成功体験が構造的に不足 | プールに弱め・多様な相手を混ぜる | プール機能は失敗済み履歴あり。再挑戦するなら suite のスタイル指標で「押しへの正の credit」を確認しながら |
| (c) 探索ほぼゼロ（ε=0.005/temp=0.05） | 一部ワーカーのみ探索強めプロファイル | TRAIN_PLAY_PROFILE で実装容易。ただし探索手がそのまま学習される問題あり（greedy フラグ未実装、§5 保留参照） |
| (d) MC ターゲットの高分散 | duplicate ベースライン（同一山4席の平均を差し引く）または IQL 系ブートストラップ | C-1 の結論が指す「ターゲット側の変更」。工事は大きいが理論的裏付けが今回初めて得られた路線 |

- Huber をオンラインに持ち込む場合は事前に報酬分布で外れ値の符号を確認（和了報酬を切ると押しが過小評価される）
- 崩れたら top-k candidates から巻き戻す

## 5. 実験プロトコル（全フェーズ共通）

1. **1介入 = 1実験**。exp/* ブランチで行い、ゲートを通ったものだけ main へ
2. **成功/中止基準を事前に書く**。例: 「suite/efficiency/shanten_regression_rate が −1pt 以上、かつ behavior/* が許容帯内、かつ test_play ペア比較の悪化が gate_sigma 以内。20k ステップで未達なら revert」
3. **A/B のパス分離**: state_file / best_state_file / tensorboard_dir / test_play.log_dir をすべて別パスに（test_play.log_dir は評価毎に rmtree されるため共有厳禁）。既存 run を control とし、checkpoint をコピーして「継続学習 N step」を比較。同一 GPU なら順番実行で可（比較は step 基準）
4. **判定**: 挙動・牌効率は suite/*（同一局面比較・ノイズほぼゼロ）、最終盤は test_play の SE 基準（差 > SE）、採用前に one_vs_three で実戦確認
5. **ロールバック**: top-k candidates + gate_sigma
